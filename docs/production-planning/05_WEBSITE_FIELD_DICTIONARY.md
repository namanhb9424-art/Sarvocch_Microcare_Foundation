# Website field dictionary

## Method and interpretation

This dictionary describes controls found in local templates and server handlers, not a public company-enquiry form. Required means required by server validation when determinable. Fields shown only after a conditional choice are labelled conditional. A browser-rendered dynamic form can expose additional hidden/repeated inputs; the exhaustive source is templates/*.html and app.py parsing helpers. No runtime UI session or submission was performed.

| Form / endpoint | Field identifiers and types | Required/validation/defaults/options/dependencies | Submission behavior / failure state |
|---|---|---|---|
| Login /login | username text; password password | Both required by lookup. No client-side default relied on. | Success clears prior session, sets uid and redirects only to same-site relative next path. Failure flashes invalid credentials and re-renders login (app.py:507-521). |
| Change password /change-password | old, new, again: password | Current password correct; new >=8 chars, includes a letter and digit, differs from old; confirmation equals new. | Hash new password, clear must_change; error flashes and retains form (app.py:524-542). |
| CRM lead /crm/new | name text; phone text; dob date; address; stage select; branch select; agent_id select | Name/phone/branch validated server-side; phone regex 10 Indian digits starting 6-9. Duplicate phone rejected. Stage values lead/prospect/customer; branch/agent options are DB-driven. DOB/address optional in source handler. | Insert customer row then redirect CRM; errors flash and no row is inserted (app.py:731-746). |
| CRM follow-up /crm/<id>/log | channel select; note; call_dir select; outcome select; duration_min number; follow_up date | Channel values include call, visit, WhatsApp, SMS, email; direction outgoing/incoming; duration 0-600. Follow-up optional. Dynamic options and required fields depend on channel. | Adds communication log and redirects customer detail (templates/crm_detail.html; app.py:761-792). |
| KYC dossier /kyc-form/new or /crm/<id>/kyc-form | Applicant: name, phone, dob, branch, agent_id. Dossier: form_date, center_no, group_no, guardian_type/name, education, religion, category, house_no, village, post_office, district, state, pincode, family rows (fm_name/age/edu/rel/occ), house_type, land_ha, livestock, bank_name/bank_acct/passbook_name, poverty_line, dist_center_m, dist_branch_km, relative_in_center/relative_name, annual_income, other_loans, current_debt, repay_freq. Co-applicant: co_name/phone/relation/relation_other/income. Repeating neighbors: nb_name/phone/email/years/remarks. Conditional spouse: h_father/h_dob/h_address/h_same_addr/h_photo. Declarations: consent_given, declaration, bureau_consent, address_verified, verify_remarks. Files: photo, signed_copy. | Applicant name 2-80 chars/no digits; phone 10 Indian digits and unique; DOB required and configured age range 18-55 by default. Branch and assigned agent valid. Form date valid/not future. Education/religion/category/state/house type/poverty line/repayment frequency must be allowed values. Village/district/PIN required; PIN six digits. Family has 1-12 rows; applicant first; each row has name, age (integer <=110) and relation. Land/income/debt/distance values numeric and bounded. Bank account optional but if entered 9-18 digits and bank required. Relative name required when relative_in_center=yes. Co-applicant is optional; if entered, valid distinct phone, allowed relation; relation text required for Other. Neighbor list capped at 3; if any contact field is entered then name and valid phone are required; email optional but valid if provided. Husband DOB/address/consent become required only when guardian_type=husband. Applicant photo required; photo/signed-copy images/files limited to PDF/JPG/PNG and 16 MB server cap. Declarations and bureau/address consent required by handler. | Server validates first; if errors, flashes each and saves no KYC/customer record. Files are written only after validations pass. New/edit is saved; print route renders dossier. (templates/kyc_form.html; app.py:1828-1849, 1869-2098, 2169-2189). |
| KYC verification /api/kyc/verify | customer_id integer; doc_type select; value text; OTP optional | doc_type aadhaar, pan or voter. Aadhaar format 12 digits starting 2-9 plus Verhoeff; PAN pattern; Voter ID 3 uppercase letters + 7 digits. Provider verification not established; local checks are not government verification. | JSON result; queue/status update path. Failure returns validation/provider-simulation error (app.py:804-839, 345-365). |
| Loan application /apply | customer_id select; product_id select; amount and tenure numbers; loan_cycle integer; purpose; previous loan rows (amount/purpose/frequency/on-time/reason/absence); monthly income fields inc_agri/inc_business/inc_job/inc_other; expense fields exp_basic/education/festival/health/emi/other; occupation/employer; docs_dep checkbox list/docs_other; doc_id/doc_address/doc_income/doc_photo uploads; insurance_wanted/insurance_for/insurance_ack; group_rec/center_rec; app_declaration. | Customer must be in user scope and have KYC form; active product must be in role scope. Amount/tenure within product bounds; cycle 1-50; prior rows max 6; income >0, net income positive, configured household-income cap and EMI ratio; at least two distinct document options; insurance_for husband/self/both + acknowledgement if yes; declaration required; uploads PDF/JPG/PNG, max 16 MB; group-only and admin-only product constraints apply. Default insurance_wanted=no; product/customer options dynamic. | On errors flashes messages and states nothing was saved; users must reselect files. On success atomically inserts application, app_extra and Submitted approval log, then redirects detail (app.py:2214-2337). |
| Approval /applications/<id>/action | action/stage; approved_amount number; remarks | Permission depends on transition (approve/disburse). Amount if supplied must be positive and no more than requested; allowed transitions are state-dependent. Remarks optional except rejection/return cases. | Adds decision row; disbursement creates loan and schedule within DB transaction; failure flashes and leaves application state unchanged (app.py:903-955). Verify transaction behavior for every transition before release. |
| Payment /pay/<id> and settlement | channel hidden; upi_id text; card_no text; expiry/CVV fields; bank select; wallet select. Channels: UPI/card/netbanking/wallet. | Payment gateway is explicitly a demo. Client collects payment-like data that must never be accepted or stored as real PAN/CVV. Bank options SBI/HDFC/ICICI/Axis/Bank of Baroda; wallet options vary by template. No production validation/provider verified. | Simulates successful payment; schedule and payment records update. Settlement quote is outstanding principal + next installment interest. Real payment success/failure/refund behavior is absent (templates/pay.html, settle.html; app.py:1087-1148, 2599-2624). |
| Product configuration /products | name; rate; min_amt/max_amt; min_tenure/max_tenure; method; fee_pct; active/admin_only/group_only | Name/rate/amount bounds/tenure bounds are required on create; method reducing or flat; numeric rates allow step 0.1. Fee default 1. Product constraints drive /apply. | POST inserts or updates product and redirects; no history/version snapshot is established (app.py:682-707). |
| Pre-GRT group /pregrt/new | branch, form_date, center_no, group_no, village, district, agent_id, pso_name/empid, bm_name/empid, leader_knows_duties, notes, member rows and seven c_* confirmations | Group size configured 2-5 by default; member identities and demographics; verification requires all required CGT confirmations; customer selection is optional/dynamic. Review remarks required when returned. | Save draft/submitted; manager verifies or returns with remarks; group application only for verified group. Errors preserve form values and save no invalid submission (app.py:2365-2455, 2538-2582). |
| Attendance /attendance | kind (in/out), lat/lng hidden; correction day date, in_time/out_time time, reason; decision remarks | Punch coordinates must be valid and inside configured branch radius; minimum hours before punch-out default 8; correction approver is based on org role/hierarchy. | Punch is recorded or refused; correction request is pending until approved/rejected. Source of GPS and accuracy are not cryptographically attested (app.py:1239-1413). |
| Field tasks /field | task title, type select (verification/collection), customer_id, officer_id, due_date, lat/lng; completion collected number >=0 and notes | Assignment restricted to manager; task/customer/officer options are DB-backed. Completion amount cannot be negative. | Marking collection updates task and creates a payment/schedule update; this critical path must be atomic/idempotent (app.py:1194-1211, 1448-1465). |
| Employees /employees; HRM /hrm | name, phone, email, designation, salary, branch, manager_id, joined, docs; leave user_id/from_d/to_d/reason; performance user_id/period/rating/notes | Phone 10 Indian digits where validated; email type; salary non-negative; rating 1-5; leave dates/reason; dropdowns DB-backed. | Branch /branches | name, code, address, phone, head_name, location text or lat/lng, radius_m | Location parsed from Google Maps URL or coordinates; radius 50-20,000m; active flag. | Save branch and refresh policy scope (app.py:2859-2903). |
| Settings /settings | hidden action; numeric policy value; holiday day/date and name | Defaults: age 18-55; group 2-5; household income limit 25,000 monthly; EMI <=60%; GST 18%; work hours 8. Rate caps/units need business confirmation. | Admin-only; updates settings or holiday and redirects (app.py:2905-2944). |
| Offline sync /api/sync | JSON items: uuid, task_id, mark_done, collected, notes, optional image data | Max 200 items/request; UUID 8-64 word/hyphen chars; image data cap <3 MB; duplicate UUID is idempotently acknowledged. | Returns accepted/duplicate/bad sets; local queue format is Flutter-side. Error/conflict/replay behavior needs formal contract (app.py:1478-1519). |

## Fields not verified

Exact internal HTML names for macro-generated KYC family rows are fm_name/fm_age/fm_edu/fm_rel/fm_occ, and neighborhood rows are nb_*; exact visible translated labels are in templates/kyc_form.html and reference constants in app.py:1869-2070. Dropdown inventories for education, religion, category, state, house type, repayment frequency and groups should be imported from the source constants and approved as business data; this document does not normalize or expand values not shown in the server validator.

There is no public B2B quotation/enquiry form. Do not reuse payment/card fields as manufacturing enquiry fields.
